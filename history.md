# Краткое описание

## Как реализовано хранение истории

- История хранится на диске в `data/history` (или в директории из `DIALOG_HISTORY_DIR`).
- Для каждого чата создается отдельный YAML-файл: `<chatId>.yaml`.
- Перед сохранением/чтением история нормализуется: остаются только сообщения с ролями `user`, `assistant`, `system` и строковым `content`.
- На каждый входящий запрос бот:
  1. читает историю чата;
  2. добавляет текущее сообщение пользователя;
  3. после ответа модели добавляет сообщение ассистента;
  4. сохраняет обновленную историю.
- Размер истории ограничивается `DIALOG_HISTORY_MAX_MESSAGES` (по умолчанию 30). Если сообщений больше лимита, сервис старается сохранить последнее `system`-сообщение и самые свежие сообщения.

## Как работает суммаризация

- После ответа модели вызывается сжатие истории.
- Сжатие включается, когда длина истории больше `DIALOG_SUMMARY_THRESHOLD` (по умолчанию 14).
- История делится на две части:
  - старая часть для суммаризации;
  - последние `DIALOG_SUMMARY_KEEP_RECENT_MESSAGES` сообщений (по умолчанию 6), которые остаются без изменений.
- Для старой части формируется отдельный prompt и отправляется в LLM (через `ollamaService.query`), где модель должна вернуть короткое резюме в 3 строках:
  - `Цель: ...`
  - `Ограничения и предпочтения пользователя: ...`
  - `Текущий статус/договоренности: ...`
- Если резюме успешно получено, история заменяется на:
  1. одно `system`-сообщение с префиксом `Краткое резюме предыдущего диалога:`;
  2. последние сообщения из текущего диалога.
- Если суммаризация не удалась или вернулся пустой текст, сохраняется исходная история без изменений.
